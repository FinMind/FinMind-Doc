# 服務狀態與可用率

FinMind 提供對外即時狀態頁：

[**status.finmindtrade.com**](https://status.finmindtrade.com)

該頁顯示 API 目前狀態、過去 **24 小時**與 **90 天**的可用率（uptime），以及歷史事件紀錄。

此可用率即 **FinMind 企業方案 SLA 的衡量基準**——企業客戶的服務水準以同一套演算法衡量，與狀態頁所呈現者一致透明。

## 可用率怎麼計算

可用率以**真實 API 流量、逐請求**衡量。完整公式鏈如下：

**1. 有效請求**

```text
有效請求 = 成功請求(2xx / 3xx) + server-side error
```

- **server-side error** 指 HTTP **5xx** 回應。
- **client error**（例如 `400` / `403` / `404` / `429` 等請求端錯誤），以及在回應送達前由用戶端中斷的連線，**不計入**有效請求，也不影響可用率。

**2. 可用率**

```text
可用率 % = 成功請求 ÷ 有效請求 × 100
```

- **24 小時**、**90 天**與**當月**數字，都是把該區間內的**請求數加總**後再計算一次，而不是把各分鐘或各日的可用率平均。
- **沒有流量的區間不計入**可用率。
- **計畫性維護**時段可排除，該時段的請求不計入分子與分母。

??? note "為什麼以請求數計算"

    以請求數為分母，錯誤比例會**等比反映**在可用率上：某區間有 1.6% 的請求以 server-side error 收場，該區間的可用率就是 98.4%。

    若改以「時間區塊是否算中斷」為單位衡量，長期存在但比例偏低的錯誤會讓每一個區塊都被視為正常，可用率恆為 100%，反而看不出服務的持續性劣化。以請求數計算可避免這個盲點，也與您實際感受到的失敗比例一致。

## 狀態分級

某時間窗有流量時，依該窗的可用率分為四級：

| 狀態 | 可用率門檻 |
| --- | --- |
| **Operational** | ≥ 99.5% |
| **Elevated Error Rates** | 95% ～ 99.5%（95% ≤ 可用率 < 99.5%） |
| **Partial Outage** | 80% ～ 95%（80% ≤ 可用率 < 95%） |
| **Major Outage** | < 80% |
| **No data** | 該區間沒有流量 |

!!! tip
    狀態頁底部也內含同樣的「How uptime is calculated」說明，可隨時查閱。
